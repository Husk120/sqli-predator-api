## 2026-07-26/27 — Engine Accuracy Session
### Fixed
- **Timeout-swallowed time-based findings**: `httpx.TimeoutException` on a `time_based` payload previously hit the generic `except Exception: continue` and was silently dropped. Now caught specifically; treated as a strong positive signal (`conf=0.65` fixed, not run through `calc_confidence`) → scores High/65%/CVSS 6.5. Applied to both `test_form` and `test_params`.
- **Stale payload sampling**: `ALL_PAYLOADS[:15]`/`[:25]` sliced a fixed prefix of a list only shuffled once at process startup — same 15/25 payloads tested forever per Render process lifetime. Fixed to `random.sample()` per parameter (later evolved into full stratified sampling, see below).
- **Reflection-filter inconsistency (2 root causes, fixed separately)**:
  1. `check_reflection()` did literal substring matching; payload mutations with inline SQL comments (`/*!12345*/` etc.) broke the match, causing identical vulnerabilities to score High/50% (clean payload) vs Info/15%/Likely-False-Positive (mutated payload) purely at random depending which variant got sampled. Fixed via `_normalize_for_comparison()` stripping comments before compare.
  2. Same issue for URL-encoding (`%2527` double-encoded quotes) — payload/response never matched literally. Fixed by adding repeated `urllib.parse.unquote()` loop to the same normalizer. **Verified against real scan reports** — mutated and clean payloads on identical parameters now classify identically.
- **Stratified payload sampling** (multiple iterations to get right): pure random sampling from the ~230-payload pool meant only a small `error_based` category (24 payloads) had a ~15% chance per scan of being drawn — causing wildly inconsistent finding counts (0-3 findings across identical re-scans of `medlife.co.ke/web/login`). Final fix: `error_based` guaranteed 100% (24/24) in both `test_form` and `test_params` (non-negotiable — this is the category proven to cause inconsistency). Other categories get partial guaranteed/sampled quotas. Final volume: **~67 payloads/form-parameter, ~53/URL-parameter** (up from original 15/25, but capped well below an earlier 142/104 draft that was rejected as too slow for Render free-tier + no persistence risk). `defaultdict` import required for category bucketing (`from collections import defaultdict`).
- **Payload database quality pass**: found and fixed — Oracle payload (`dbms_pipe.receive_message`) was misclassified under `error_based` (it's actually time-based), moved to `time_based`. Dead `WHITESPACE` mutation array wired in. `mutate_payload()`'s `len(kw) > 2` guard was silently excluding "OR"/"AND" from comment-injection mutation — fixed to `>= 2`. Mutation keyword list expanded to include DB-specific function names (`EXTRACTVALUE`, `UPDATEXML`, `WAITFOR`, `pg_sleep`, etc.) so mutation actually targets the signatures that matter.
- **New payload coverage added**: SQLite error_based + time_based (previously zero coverage). New `auth_bypass` category (11 templates, login-bypass-specific, e.g. MD5-hash UNION bypass). New `nosql_probe` category (4 string-based MongoDB-style payloads) + `NoSQL` error-pattern signatures added to `SQL_ERROR_PATTERNS`. `syntax_probe` expanded with backtick/comma/semicolon/null-byte entries. Boolean true/false deduplicated (removed comment-syntax-only duplicates), added numeric/parenthesized/comparative variants.
- **Scan configuration persistence**: previously scan settings (crawl_depth, request_delay, thresholds, headers/2nd-order toggles) were used transiently and discarded — no way to know what config produced a given report. Now stored in `create_scan()`'s initial dict as a `config` object, returned via `/status` and `/report`, displayed in a "Scan Configuration" card on the report page, included in JSON/Markdown/HTML exports. **Deliberately stores `auth_used: bool` instead of raw `auth_cookie`/`auth_creds`** so exported reports never leak session tokens/credentials.
- **`scan_log` end-to-end wiring**: previously `scan_log` was never initialized, never appended to, never returned by `/status` — Live Activity Feed always showed "0 entries". Fixed: initialized as `[]` in `create_scan()`, `log_event()` helper appends during `run_scan`/`test_form`/`test_params`, returned in `/status`.
- **`isStalled` false-positive warning**: was based on the coarse phase-level `progress` percentage (only moves at ~10/30/70/90/100%), which falsely triggered "may be cold-starting" during long, genuinely-active parameter testing. Fixed to track `scan_log.length` growth instead — only warns if truly no new log activity for 90s.
- **Invalid Date bug**: `/api/scan/{id}/status` never returned `timestamp` at all; `app/scans/page.tsx`'s `normalizeScanResult` had no fallback (unlike the detail page, which did). Fixed with the same fallback pattern.
- **crawl_depth mismatch**: frontend dropdown offered value `3` ("Two levels deep"), backend `ScanRequest` capped at `le=2` — silent 422 rejection shown only as generic "Failed to start scan" (FastAPI's `detail` field wasn't parsed). Fixed backend to `le=3`, fixed frontend to surface real `detail` messages.
- **`NameError: name 'get_scan' is not defined`**: `log_event()` in `api/scan.py` called `get_scan()` without importing it from `lib.store` — broke every scan immediately after the scan_log feature shipped. One-line import fix.
- **Hardcoded light-mode styling bugs** (recurring pattern, fixed each time found): "No SQL injection vulnerabilities detected" empty state, risk banner (Critical/High findings), Live Activity Feed card — all had leftover `bg-white`/hex light colors instead of dark theme CSS variables.
- Firebase security incident (predates this session): exposed private key in logs, rotated, old key confirmed revoked in GCP console, new key confirmed set in Vercel.
